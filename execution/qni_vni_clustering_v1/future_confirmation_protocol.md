# Frozen future confirmation protocol

Freeze this protocol before any post-2026-09-01 outcomes are inspected. It is
the path from historical development evidence to a genuinely later test; it is
not executed by the current retained-data campaign.

## Freeze record

- Record the selected connector/target/lead-band model, K, clustering method,
  feature order, generator representation, OOD threshold, calibrator and alert
  thresholds by content hash.
- Record the configuration, code revision, dependency versions, source schema
  versions and complete model-bundle hashes.
- Preserve the historical development report unchanged. Later data cannot be
  used to revisit the frozen choice before the confirmation score is issued.

## Information availability

- Log source, product, run/vintage, delivery interval, generated time, actual
  receipt time, age and raw/normalised hashes for every feature row.
- Admit a value only when receipt time is no later than the forecast origin.
  Keep each regional/cross-regional row on a coherent vintage.
- Missing or late required inputs invoke the frozen pooled fallback; do not use
  a later revision or realised observation.
- Preserve fixed UTC+10, interval-ending semantics, native five-minute source
  records, signed directional limits and target-specific origin-minus-30-minute
  anchors.

## Evaluation

- Accumulate at least eight complete evaluation weeks per primary forecast
  cell and at least 30 contraction incidents per direction before issuing a
  supported warning comparison.
- Score the exact frozen metrics: point error and paired effect, 80%/95%
  coverage and width, capacity overstatement, event recall/precision/Brier
  score and joint false alerts per exposure day.
- Compare on identical finite rows against persistence, daily/weekly
  persistence, the frozen unclustered control and matched AEMO vintages when
  eligible.
- Publish results by connector, target, lead band, season, delivery period,
  cluster state and data-quality cohort. Report coverage lost to matching.

## Decision boundary

The confirmation run remains research-only until its receipt-time provenance,
model-reload parity, risk support, calibration, report validation and explicit
promotion review all pass. A strong historical or later test does not
automatically update production routing.
